# 第 7 章 · 令牌·用户·分组

> 本章目标：讲清"谁能用 newapi、用什么、受什么限制"——令牌、用户、分组、限流。读完你能为不同客户端签发合适的令牌，并理解分组如何隔离渠道与计费。含实战。

---

## 7.1 令牌（Token）：你的调用钥匙

**令牌**是 newapi 发给客户端的调用钥匙——客户端用它**代替上游 Key** 调用 newapi。上游真实 Key 只存在渠道里（第 4 章），客户端永远拿不到，这就是 newapi"密钥管理"的价值。

- 令牌本质是一串字符串（形如 `sk-xxxxxxxx`，`sk-` 前缀可有可无）。
- 一个令牌绑定一个**用户**和一个**分组**。
- 令牌可在多个端点复用（`/v1/chat/completions`、`/v1/messages`、`/v1beta/...` 都能用同一把）。

## 7.2 创建与管理令牌

Web：**控制台 → 令牌（`/console/token`）→ 添加令牌**。高级配置（〔research/06〕）：

| 配置项 | 含义 |
|---|---|
| 名称 | 便于识别（如"claude code 专用"） |
| **额度** | 该令牌可用配额上限（配额单位见第 8 章；1 美元=50 万点） |
| **无限额度** | 勾选则不限额度（按用户额度扣） |
| **过期时间** | 令牌失效日期 |
| **模型限制** | 白名单：该令牌**只能**用这些模型（留空=用分组内全部） |
| **IP 白名单** | 仅这些 IP 能用该令牌 |
| **分组** | 绑定的分组（决定可用渠道与计费倍率） |

⚠️ 令牌列表/详情里 Key 以掩码展示；**完整 Key 可随时通过"复制 Key"重新获取**（`POST /api/token/:id/key`，`controller/token.go:80-95`；批量取 `POST /api/token/batch/keys`）。创建时前端会弹窗提示复制一次，但**并非"只能看一次"**。这与渠道里的"上游 Key"是两回事，别混淆。

> 管理员可用 `sk-{token}-{channelId}` 格式让某令牌**指定命中某渠道**（仅管理员，普通用户禁止，`middleware/auth.go:505-513`）——排错/测试时很有用。⚠️ 指定渠道会**跳过分组与类型匹配**：若令牌协议（如 Claude）与被指定渠道类型不一致，会触发协议转换（有损），仅供排错，勿用于生产流量。

## 7.3 用户与角色

- **普通用户**：注册账号，有个人额度，可创建令牌、查日志、充值。
- **管理员**：在"用户管理"（`/console/user`）改任意用户的角色/分组/配额/启停。
- **Root**：最高权限，能进"系统设置"（`/console/setting`）、性能监控、自定义 OAuth 等。

注册方式（〔research/06〕）：账号密码 + 邮箱验证码，或 GitHub/Discord/LinuxDO/OIDC/Telegram/**微信** OAuth。

## 7.4 分组（Group）：渠道与计费的隔离

**分组**是渠道的集合，决定"这个用户/令牌能用哪些渠道"，并可设**差异化计费倍率**。

- 渠道在 `Group` 字段填分组（逗号多组）；令牌绑定一个分组。
- **auto 组**：令牌绑定 `auto` 时，`GetUserAutoGroup`（`service/group.go:46`）求「管理员配置的 auto 分组 ∩ 该用户可用分组」得到**候选分组列表**，再由 `service/channel_select.go` 在其中挑渠道。
- **跨分组容灾**（两种）：①某分组无可用渠道时自动换到下一组（`channel_select.go:107-130`，对所有 auto 令牌生效）；②渠道失败后跨组重试（`channel_select.go:138`，需令牌 `CrossGroupRetry=true`，`model/token.go:30`）。

> 实战心法：把"高质量无损渠道"放 `default`、便宜备用放 `backup`，令牌绑 `auto` → default 不可用时回退 backup。⚠️ **跨组容灾的代价**：回退到下一组时**不校验渠道类型**——若 backup 是异类型（如 OpenAI 中转），会从无损降级为有损（协议转换）。**要保无损，default 与 backup 必须同协议族**；否则把 backup 当"能用但有损"的降级方案并告知用户。

## 7.5 模型限流

newapi 有多层限流（默认值，`common/init.go`）：

- **API 级**：360 次/180 秒（`GlobalApiRateLimit`，`init.go:122-123`）。
- **Web 级**：120 次/180 秒（`GlobalWebRateLimit`，`init.go:126-127`）。
- **关键操作**：20 次/1200 秒（`init.go:130-131`）。
- **模型请求限流**（`ModelRequestRateLimit` 中间件，`middleware/model-rate-limit.go`）：作用于模型转发端点，**按用户 ID 计数**（名字里的 Model 指作用于模型端点，**非按模型维度**），可按分组覆盖两个上限——格式 `{"分组":[总请求数(含失败), 成功请求数]}`，窗口为全局 `ModelRequestRateLimitDurationMinutes`（默认 1 分钟），`0`=该维度不限。例 `{"default":[200,100]}` = default 组每分钟总请求≤200、成功≤100。

限流在多节点下：共享 Redis 时额度跨节点共享；每节点独立 Redis 则各算各的（第 3 章）。

## 7.6 ★实战：为 claude code 签发"无损透传"令牌

目标：给 claude code 一把**只能走 Claude 模型、走 Anthropic 无损渠道**的令牌，从源头杜绝"错配有损"。

**前提（第 4 章已配）**：已建 Anthropic 类型渠道（Type=14，开 `PassThroughBodyEnabled`，`Group=default`，`Models` 含 claude 模型）。⚠️ **关键纪律**：`default` 组内**凡声明了 `claude-*` 模型的渠道，都必须是 Anthropic 类型（同协议族）**——系统只按"分组+模型名"选渠道（`ability.go:93-95`、`channel_cache.go:114-208`），**不按渠道类型筛选**；若组内混入也声明了 claude 模型的 OpenAI/中转渠道，会被选中并触发协议转换（有损）。

**步骤**：
1. 控制台 → 令牌 → 添加令牌。
2. 名称：`claude-code`。
3. **模型限制**：填 `claude-sonnet-4-5,claude-opus-4-8`（只允许 Claude 模型 → 即便配错渠道，也不会跑到非 Claude 模型）。
4. **分组**：`default`（即上面那个 Anthropic 渠道所在组）。
5. 额度：按需（无限或设上限）。
6. 创建 → **立即复制令牌字符串**。
7. 配置 claude code（第 11 章详述）：
   ```
   ANTHROPIC_BASE_URL=https://<your-newapi-host>
   ANTHROPIC_AUTH_TOKEN=<刚复制的令牌>
   ```

**为什么无损**：
- claude code 打 `/v1/messages`（`RelayFormatClaude`）→ 命中 `default` 组的 Anthropic 渠道（**因人为保证组内只有 Anthropic 渠道声明了 claude 模型——定律②是配置纪律，非系统自动筛选**）→ 该渠道开 PassThrough（定律③）→ **请求体字节级无损直通**到 Anthropic 上游。
- ⚠️ **模型限制只保"模型名正确"，不保"渠道类型匹配"**——它**不是**防协议转换的保险；防转换靠的是上面"组内类型纯净"的纪律。
- ⚠️ **流式边界**：claude code 默认流式，响应在 newapi 侧逐事件重打包——**事件内容等价、非字节级**（前言无损边界表）；上行**请求体**才是字节级无损。

**验证**：日志确认命中的渠道是 **Anthropic 类型**、模型是 claude-…、消耗正常；claude code 侧响应质量与直连一致（流式做 SSE 事件内容 diff，非字节 diff；方法见第 9 章 9.6、第 11 章 11.9）。

## 7.7 本章小结

- **令牌**= 调用钥匙，绑定用户+分组，可限额度/模型/IP/过期；**完整 Key 可随时重新获取**（`POST /api/token/:id/key`）。
- **用户**分普通/管理员/Root（OAuth 含微信）；**分组**隔离渠道与计费，`auto` 组支持跨组容灾（⚠️ 回退异类型组会有损）。
- 限流：API 360 / Web 120 / 关键操作 20·1200s；模型请求限流按用户 ID、可分组覆盖 `[总请求,成功请求]`。
- **无损实战纪律**：模型限制只保模型名；**防协议转换靠"分组内渠道类型纯净"**（系统不按类型筛选）+ 开 PassThrough；流式响应是事件等价、非字节级。
