# 第 6 章 · 配置与参数调教

> 本章目标：讲透 new-api 的配置体系，并解决核心主线的一个关键问题——**如何在"透明无损"的前提下，对个别模型（如 GLM-5.2）微调 `max_tokens`**。它直接建立在第 5 章"无损直通 ↔ ParamOverride 互斥"的结论之上。
>
> 本章是核心章，含 GLM 实战。

---

## 6.1 setting 体系全景

new-api 的配置用"反射式 ConfigManager"统一管理（`setting/config/config.go`）：

- 每个模块在 `init()` 里 `config.GlobalConfig.Register(name, &instance)`（`config.go:28`），模块名即 DB `options` 表的前缀键（如 `claude.default_max_tokens`）。
- `LoadFromDB` 按前缀 `name.` 拆扁平键 → 反射回填（`config.go:42-68`）；map 字段用全新 map 反序列化（保证删除的 key 能清掉，:255-263）。
- 改设置走"系统设置"页或 API，重启不丢。

主要模块（`setting/` 下）：

| 模块 | 职责 | 关键配置 | 改请求? |
|---|---|---|---|
| `model_setting/global.go` | 全局开关 | `PassThroughRequestEnabled`(直通总开关)、`ThinkingModelBlacklist`、`ChatCompletionsToResponsesPolicy` | 是(直通跳过所有改写) |
| `model_setting/claude.go` | Claude 专属 | `DefaultMaxTokens`(按模型 map,默认 8192)、`ThinkingAdapterEnabled`、`ThinkingAdapterBudgetTokensPercentage`(0.8) | 是(注入 max_tokens) |
| `model_setting/gemini.go` | Gemini 专属 | `SafetySettings`、`VersionSettings`、thinking adapter | 是(版本/安全/裁剪) |
| `model_setting/qwen.go` / `grok.go` | 通义 / Grok | 同步出图模型 / 违规扣费 | 否 |
| **(无 `model_setting/openai.go`)** | — | **OpenAI 侧无按模型默认参数注入** | — |
| `reasoning/suffix.go` | 推理后缀解析（请求侧） | `EffortSuffixes` / `OpenAIEffortSuffixes` / `DeepSeekV4EffortSuffixes` | 是(剥后缀→注入 thinking) |
| `ratio_setting/*` | 计费倍率 | model_ratio / group_ratio / cache_ratio | 否(纯计费) |
| `operation_setting/*` | 运营 | 通用/监控/配额/令牌/支付/渠道亲和/状态码区间/签到 | 否(部分影响路由限额) |
| `system_setting/*` | 系统 | discord/oidc/passkey/fetch/legal | 否 |
| `billing_setting/*` | 计费 | tiered_billing(阶梯表达式) | 否 |
| `performance_setting/*` | 性能 | 指标采集 | 否 |

## 6.2 ★请求改写执行顺序（必懂）

这是理解"哪个配置先生效、谁覆盖谁"的关键。一次请求的改写按以下顺序执行（越靠后越接近上游，后执行覆盖先执行）：

```
【OpenAI/GLM 路径】校验 → ModelMapping → 适配器Convert → SystemPrompt注入 → Marshal → RemoveDisabledFields → ParamOverride → 发上游
【Claude 路径】  校验 → ModelMapping → DefaultMaxTokens/reasoning后缀 → SystemPrompt注入 → 适配器Convert → Marshal → RemoveDisabledFields → ParamOverride → 发上游
```

> 两条路径里 **ParamOverride 都是最后一步**（能覆盖前面所有改写，所以是"微调个别参数"的最强工具）。格式相关的前置改写（Claude 的 DefaultMaxTokens/reasoning 后缀、OpenAI 的 StreamOptions）在 ModelMapping 之后、Marshal 之前发生。⚠️ 注意 GLM 走的是 **OpenAI 路径**（Convert 在 SystemPrompt 之前）。

- **ParamOverride 是最后一步**，能覆盖前面所有改写（所以它是"微调个别参数"的最强工具）。
- ⚠️ **PassThrough（直通）是总开关**：全局 `PassThroughRequestEnabled` 或渠道 `PassThroughBodyEnabled` 任一为真，就跳过 Convert/RemoveDisabledFields/ParamOverride/SystemPrompt，原样转发（`claude_handler.go:157`、`compatible_handler.go:97`）——这是"透明无损"的硬件级保障，但也意味着**开了直通，所有改写（含 ParamOverride）对该渠道失效**（第 5 章 5.9）。

## 6.4 ★ParamOverride DSL 全集（`relay/common/override.go`）

ParamOverride 是"在网关侧微调请求参数"的最强工具，支持两种写法：

**简单（legacy）模式**：顶层 key 直接合并
```json
{"max_tokens": 8192, "temperature": 0.8}
```

**高级（operations）模式**（推荐，支持条件/路径/变量）：
```json
{
  "operations": [
    {
      "path": "max_tokens",
      "mode": "set",
      "value": 4096,
      "keep_origin": true,
      "conditions": [{"path": "model", "mode": "prefix", "value": "glm-5.2"}]
    }
  ]
}
```

- **23 种 mode**：`set/delete/move/copy/prepend/append/trim_prefix/trim_suffix/ensure_prefix/ensure_suffix/trim_space/to_lower/to_upper/replace/regex_replace/return_error/prune_objects/set_header/delete_header/copy_header/move_header/pass_headers/sync_fields`（`override.go:756-967`）。
- **conditions**：8 种比较（`full/prefix/suffix/contains/gt/gte/lt/lte`）+ 逻辑 `AND/OR` + `invert` 反选 + `pass_missing_key` 缺失处理。
- **路径语法**：`temperature`、`messages.0.content`（首条）、`messages.-1.content`（末条）、`tools.*.function.name`（通配）、`metadata.user.name`。
- **内置变量**：`model`（映射后上游名）/ `upstream_model` / `original_model`（映射前客户端名）/ `is_retry` / `last_error` / `request_headers`（`override.go:2048-2105`）。
- **`keep_origin`**（:767-769，**仅对 `set`/对象合并等部分 mode 生效**；对 `delete`/`move`/`replace`/`regex_replace` 等被忽略）：目标路径已存在则跳过 = "仅缺失时补"。注意"缺失时补默认"本身是**请求体字节修改**（新增字段），严格字节级非无损，属"语义无损"。
- **`return_error`**（:881-887）：按条件直接拒绝请求。
- **审计**：敏感路径前缀（model/original_model/messages/input/contents/system/service_tier 等，:29-43）或 DEBUG 模式记到 `info.ParamOverrideAudit`，进管理员日志。

> ⚠️ **条件匹配的"模型名"是映射后的上游名**（ParamOverride 在 ModelMappedHelper 之后运行，context 取 `UpstreamModelName`，`override.go:2054`）。要按客户端原名匹配用 `original_model`。

## 6.5 RemoveDisabledFields：反向改写（默认删字段）

`RemoveDisabledFields`（`relay_info.go:798-887`）默认**删**这些字段（防意外计费/合规/隐私）：

- `service_tier`、`inference_geo`、`speed`、`safety_identifier`、`stream_options.include_obfuscation`
- `store`（默认保留，仅 `DisableStore` 时删）

要保留某字段，就在渠道"其他设置"开对应 `Allow*`（`AllowServiceTier`/`AllowInferenceGeo`/`AllowSpeed`/`AllowSafetyIdentifier`/`AllowIncludeObfuscation`，`dto/channel_settings.go:36-56`）。

> 开 PassThrough 时整个 RemoveDisabledFields 被跳过（`relay_info.go:799-801`），全部字段随原始字节保留。

## 6.6 reasoning / thinking（请求侧 vs 响应侧，勿混）

两个文件职责完全不同：

- **`setting/reasoning/suffix.go` = 请求侧**：`EffortSuffixes`（:9）含 `-max/-xhigh/-high/-medium/-low/-minimal`，剥后缀并注入对应字段。⚠️ **`-thinking` 不在 EffortSuffixes 里**，它走各 adaptor 硬编码 `HasSuffix` 分支。
  - Claude：`-thinking` → `Thinking.Type="enabled"` + BudgetTokens=MaxTokens×0.8（`claude_handler.go:76-108`）。
  - **OpenRouter 渠道**（仅 `ChannelTypeOpenRouter`）：`-thinking` → `reasoning.enabled=true`（`openai/adaptor.go:256-293`，块在 :251 OpenRouter 分支内；**普通 OpenAI 渠道不走**）。
  - Gemini/Vertex：剥后缀（`gemini/adaptor.go:145`）；ThinkingBudget 由转换层按 `thinking_config` 注入。
  - `ThinkingModelBlacklist`（`global.go:44`）：名单内模型**保留**后缀不剥离。
- **`relay/reasonmap/reasonmap.go` = 响应侧**：finish_reason/stop_reason 跨协议映射（`end_turn→stop`、`max_tokens→length` 等），与 thinking 无关。

## 6.7 maxTokensLimit：不截断，只拒绝

`maxTokensLimit = math.MaxInt32/2`（`valid_request.go:120`），`exceedsMaxTokensLimit` 只做**上界拒绝**（>该值返回 400），**绝不静默 clamp**。OpenAI/Claude/Gemini/Responses 四种格式的 max_tokens 族字段都在各自 validator 调用它。

→ 正常值（几千~几万）完全不受影响；只有天文数字（>10 亿）才被拒。**改 max_tokens 的方案都不受此上限干扰。**

## 6.8 ★实战：针对 GLM-5.2 修改 max_tokens（三方案）

**先明确代码事实**（〔research/10〕）：GLM-5.2 走 OpenAI 兼容路径（`/v1/chat/completions`）时——
- ❌ **没有**类似 Claude 的 `GetDefaultMaxTokens`（它只在 `claude_handler.go:50-53` 被调用，仅处理 `/v1/messages`）。
- ❌ **`model_setting` 下没有 `openai.go`**，无 OpenAI 侧按模型默认；`compatible_handler.go` 全程无 max_tokens 默认注入。
- ✅ **唯一手段是渠道 ParamOverride**（operations set max_tokens）。

### 方案 A（强烈推荐）：ParamOverride + conditions + keep_origin
**适用**：客户端不传 max_tokens 时给合理默认，客户端传了就尊重——**语义无损**（客户端已传时字节级不动；未传时补默认属请求体新增字段）。

渠道编辑→"参数覆盖"：
```json
{
  "operations": [
    {
      "path": "max_tokens",
      "mode": "set",
      "value": 4096,
      "keep_origin": true,
      "conditions": [{"path": "model", "mode": "prefix", "value": "glm-5.2"}]
    }
  ]
}
```
- `keep_origin:true`（仅 `set` 等 mode 生效）：目标路径已存在则跳过 = "仅缺失时补"。客户端已传时**字节级不动**；未传时补默认属请求体新增。
- `conditions` 精准锁定 GLM-5.2（注意匹配的是映射后的上游模型名；按客户端原名用 `original_model`）。
- **无损性**：✅ 语义无损（不覆盖客户端显式值；未传时补默认属请求体新增字段，严格字节级非无损）。
- ⚠️ **该渠道必须不开 PassThrough**（否则 ParamOverride 失效，见第 5 章 5.9）。

### 方案 B：ModelMapping 重定向到专用渠道 + 无 conditions 的 ParamOverride
**适用**：给 GLM-5.2 完全隔离的策略。
1. 新建"GLM-5.2 专用"渠道（`Models` 只含 glm-5.2，**不开 PassThrough**）。
2. 该渠道 ParamOverride：`{"operations":[{"path":"max_tokens","mode":"set","value":4096,"keep_origin":true}]}`。
3. 客户端若用别名，在 ModelMapping 里 `glm-pro → glm-5.2`，靠分组/优先级导流。
- **无损性**：✅ 无损（keep_origin）。

### 方案 C（仅当客户端走 `/v1/messages`）：复用 Claude DefaultMaxTokens
**适用**：客户端用 Anthropic Messages 协议调 GLM-5.2（智谱有兼容层）。
1. 系统设置→模型设置→Claude→编辑 `default_max_tokens`，加 `"glm-5.2": 4096`（保留 `"default":8192` 兜底）。
2. 代码路径 `claude_handler.go:50-53`：仅 `MaxTokens==nil||*0` 才填（**近似** keep_origin；注意客户端显式传 `max_tokens=0` 也会被覆盖，与严格 keep_origin 在 0 值上不同）。
- ⚠️ **只对 Claude 格式请求生效**，`/v1/chat/completions` 不走。
- ⚠️ **该渠道同样必须不开 PassThrough**：注入虽在 PassThrough 判断（:157）之前执行，但直通分支用原始字节，注入成果被丢弃。
- **无损性**：✅ 语义无损（仅 nil/0 时补默认）。

### 三方案对比
| 方案 | 落点 | 适用路径 | 是否需要关 PassThrough | 无损 |
|---|---|---|---|---|
| A ParamOverride+keep_origin+conditions | 渠道 ParamOverride | 任意（GLM 走 OpenAI 路径用此） | 是（该渠道） | ✅ |
| B 专用渠道+ParamOverride | 隔离渠道 | 任意 | 是（专用渠道） | ✅ |
| C Claude DefaultMaxTokens | 全局 Claude 设置 | 仅 `/v1/messages` | **是**（注入在 PassThrough 判断前执行,但直通分支用原始字节,注入成果被丢弃,与 A/B 同） | ✅ |

> 若智谱上游 max_tokens 用别的键名（部分厂商 `max_output_tokens`），把 `path` 改成对应键即可。reasoning/thinking 调教同理用方案 A 的 DSL 直接 `set` 对应路径，**不要依赖后缀机制**（GLM 走 openai adaptor 的后缀逻辑主要针对 OpenRouter 分支）。

## 6.9 本章小结

- 配置三层存储：DB `options` 表（扁平 `模块.键`）→ ConfigManager 反射回填 → 内存全局单例。
- **请求改写执行顺序**（OpenAI/GLM 路径）：校验→ModelMapping→Convert→SystemPrompt→Marshal→RemoveDisabledFields→**ParamOverride**→发上游（Claude 路径 Convert 在 SystemPrompt 之后）。ParamOverride 最后一步，能覆盖前面所有。
- **PassThrough 是总开关**：开则跳过一切改写（含 ParamOverride）——无损与调参在同一渠道互斥。
- **ParamOverride DSL**：23 mode / conditions / keep_origin / 通配路径 / 内置变量；`keep_origin` 是"无损补默认"的关键。
- **maxTokensLimit 只拒绝不截断**；改 max_tokens 不受其干扰。
- **GLM-5.2 改 max_tokens**：OpenAI 路径无默认注入，唯一手段是渠道 ParamOverride + `keep_origin:true`（方案 A 推荐）；走 `/v1/messages` 才能用 Claude DefaultMaxTokens（方案 C）。
